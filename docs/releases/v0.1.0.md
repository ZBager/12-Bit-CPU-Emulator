# 0.1.0 - Gniezno

The first tagged release, and the first that runs anywhere but Windows.

The emulator was written on Windows as a WPF application on .NET Framework 4.7.2, and had sat
untouched since early 2024. It is now a single Avalonia 12 / .NET 10 codebase that builds, tests
and packages for Linux, macOS and Windows.

## Downloads

Every build is self-contained: the .NET runtime is bundled, so nothing needs installing.

| Platform | Asset |
| --- | --- |
| Linux (x86_64) | `CpuEmulator-v0.1.0-x86_64.AppImage` |
| macOS (Apple Silicon) | `CpuEmulator-v0.1.0-osx-arm64.tar.gz` |
| macOS (Intel) | `CpuEmulator-v0.1.0-osx-x64.tar.gz` |
| Windows (x64) | `CpuEmulator-v0.1.0-win-x64.zip` |

On Linux, `chmod +x` the AppImage before running it.

## Getting started

Launch the app, press **Load Program**, and pick one of the listings from `data/` — they ship
inside the package. `program.txt` is a bubble sort over a descending array; press **Run** and
watch it sort in memory, or **Next Step** to walk it one instruction at a time.

You can also pass a listing straight in:

```
CpuEmulator data/program.txt
```

## macOS: first run

These builds are **unsigned**. macOS quarantines unsigned apps downloaded from the internet and
reports them as *"damaged and can't be opened"* — misleading wording; the download is fine. Clear
the quarantine flag once:

```
xattr -dr com.apple.quarantine "CPU Emulator.app"
```

## Verifying a download

```
sha256sum -c SHA256SUMS.txt --ignore-missing
```

## What's in this release

- **Cross-platform.** One codebase for Linux, macOS and Windows, on .NET 10.
- **A tested CPU.** 57 tests, where there were none. The suite pins exact behavior: `program.txt`
  must halt after precisely 1655 instructions with its array sorted, checked against a full
  4096-word RAM snapshot.
- **Six pre-existing bugs fixed**, including two that would have broken the app outright on the
  new runtime — `Thread.Abort()` behind the Stop button, which throws on .NET 10, and program
  loading, which could never have resolved its path on Linux. A third had `Data12Bit`'s
  constructor quietly bypassing its own mask, so the type violated the 12-bit invariant it exists
  to enforce.
- **Errors are visible.** Invalid opcodes used to terminate the process silently; they now report
  the offending address and decode level in the status bar.
- **The CPU can be reset** and run again without restarting the app.
- **Corrected documentation.** The README's opcode table contradicted the implementation — `E` and
  `F` were swapped, and a documented "Clear Flags" instruction was never implemented.

## Known limitations

- **The program editor is not implemented.** Its panel is present but disabled. Programs are
  hand-assembled hex listings for now.
- **The macOS builds are unsigned and lightly exercised.** CI builds them on a real macOS runner
  and the test suite passes there, but the bundles themselves have had little real-world use.
  Reports welcome.
- Instruction timing is illustrative, not cycle-accurate.
